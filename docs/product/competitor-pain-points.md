# 경쟁 노트 앱 불편 사항 조사 (CetusNote 기회 분석)

- 조사일: 2026-11-26
- 대상: Notion, Obsidian, Evernote, Apple Notes, Bear, Logseq, Craft, Anytype, AFFiNE, UpNote, Joplin, OneNote, Capacities (Notesnook, GoodNotes 등 일부 보조 참고)
- 방법: 웹 검색(표준 모드) 약 30회와 원문 확인 페이지 4건. 검색 결과에 보이는 URL만 인용했다. 인용문은 실제로 확인한 페이지에서만 옮겼다.
- 주의: 출처 대부분은 사용자 후기 모음 사이트, 포럼 글, 개인 블로그, 벤더 비교 페이지다. Reddit 본문은 거의 잡히지 않았다. 빈도는 "여러 독립 출처에서 반복됐는가"로 매긴 주관 판단이며 정량 조사가 아니다.

## 1. 요약: CetusNote가 노려볼 상위 10개 불편

| 순위 | 불편                                            | 왜 CetusNote에 맞는가                                                                                                                                          |
| ---- | ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 동기화 실패와 조용한 데이터 손실에 대한 불신    | 동기화 서버가 없고 페이지 1개 = JSON 1개라 이 범주 자체가 줄어든다. 원자적 쓰기, 휴지통, 버전 기록, 백업이 이미 있으니 "잃지 않는 앱"을 전면에 내세울 수 있다. |
| 2    | 구독료 인상과 AI 기능 묶어 팔기                 | 계정·구독이 없는 로컬 앱은 가격 불안을 근본적으로 없앤다. 가격 정책을 명확히 적는 것만으로 차별점이 된다.                                                      |
| 3    | 페이지·데이터베이스가 커질수록 느려짐           | 메모리 인덱스 검색과 로컬 파일 읽기는 빠르게 만들기 쉽다. 대용량 벤치마크를 공개하면 신뢰를 얻는다.                                                            |
| 4    | 내보내기 시 데이터베이스 구조 손실              | Markdown 내보내기가 있으므로, 컬렉션(표·보드)을 표 형태로 잃지 않고 내보내는 명세를 정하면 강점이 된다.                                                        |
| 5    | 록인: 나갈 때 정리 비용과 해지 절차의 불편      | 한 페이지가 한 JSON 파일이라 파일 탐색기만으로 꺼낼 수 있다. 이 점을 문서로 명시한다.                                                                          |
| 6    | AI 기능을 끌 수 없고 기본값으로 밀어넣음        | 내장 AI 글쓰기가 범위 밖이고 MCP는 사용자가 켜는 방식이므로 "AI 없는 기본값"을 명확히 할 수 있다.                                                              |
| 7    | 플러그인·설정 과잉과 그로 인한 피로             | 플러그인 시스템 없이 기본 기능을 완성도 있게 제공하는 쪽이 맞는 포지션이다.                                                                                    |
| 8    | 태그·폴더·링크 체계가 헷갈리고 태그 계층이 없음 | 폴더 + 태그 + 컬렉션을 역할별로 나누고 설명을 분명히 하면 된다. 태그 계층은 개선 여지다.                                                                       |
| 9    | 표·데이터베이스 편집이 느리고 불편함            | 컬렉션 뷰(표·보드·달력)를 Tiptap 블록 편집과 함께 제공한다는 점이 직접 대응 지점이다.                                                                          |
| 10   | 오프라인이 부분 지원이거나 페이지별로 켜야 함   | 로컬 우선 구조라 기본이 오프라인이다. 이 점을 기능 소개 첫머리에 둘 수 있다.                                                                                   |

## 2. 카테고리별 표

빈도 기준: 높음 = 3개 이상 독립 출처에서 반복, 중간 = 2개 출처 또는 한 출처에서 여러 사례, 낮음 = 단일 사례 또는 오래된 출처.

## 4. 출처 품질에 대한 주의

- Reddit과 Hacker News의 최신(2025~2026) 본문을 거의 확인하지 못했다. HN 검색 결과는 2019년 Notion 출시 글 중심이었다.
- 상당수가 2차 요약 사이트(Checkthat.ai, Tooliverse, Remio, Pulse.bot, Sacra, Aitoolsatlas 등)다. 특히 Remio와 Unmarkdown은 자사 제품과 관련된 주장이 있어 이해관계가 있다. 표에서는 "2차 요약"으로 표시했다.
- 원문을 직접 확인한 출처: Notion 공식 블로그, Joplin 블로그 글(2022년 작성), Evernote 가격 관련 TidBITS 포럼 글(2026), Anytype 사후 분석(2026-02). 나머지는 검색 결과 요약에 의존했다.
- 날짜가 불분명하거나 오래된 출처가 섞여 있다. Logseq 데이터 손실 글과 Joplin 블로그 글은 오래됐고, MacRumors 글은 날짜를 알 수 없다. 해당 행에 표시했다.
- Notion 오프라인 모드 관련 캐시 시간(72시간/24시간)은 벤더 블로그 수치라 확인되지 않았다. 문서에 넣지 않았다.
- Evernote "AI 기능 기본 활성화" 주장은 검색 요약에 있었으나 원출처를 확인하지 못했다. 표에서는 원문을 확인한 TidBITS 글의 AI 불만만 인용했다.
- 빈도는 조사한 출처 수 기준의 주관 판단이다. 정량 조사가 아니다.
- 이 문서는 커밋하지 않았다. 현재 브랜치(main)에서 다른 에이전트가 커밋 작업 중이다.
