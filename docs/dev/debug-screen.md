# Debug 화면 명세

화면을 조립하기 전에 **모든 컴포넌트를 실제 앱 안에서 상태별·테마별로 한 번에 확인하는 개발 전용 화면**이다.
OpenDesign의 `components.html`(컴포넌트 시트)을 실제 코드로 옮긴 것이라고 보면 된다.

## 1. 원칙: 컴포넌트 우선 게이트

1. 컴포넌트는 **Debug 화면에서 `Ready`가 된 뒤에만** 화면(`screens/`)에서 쓸 수 있다.
2. `Ready` 조건:
   - [`components.md`](../design/components.md)에 적힌 변형·상태를 모두 보여 준다.
   - 라이트/다크 모두에서 OpenDesign 시트의 해당 섹션과 비교를 마쳤다.
   - 키보드 포커스 링이 보이고, 클릭할 수 있는 요소는 Tab으로 닿는다.
3. `감사 완료`는 UI 감사(취향·위계 체크리스트 + Web Interface Guidelines)을 통과한 상태다.

## 2. Storybook과의 역할 분담

|           | Storybook                  | Debug 화면                                         |
| --------- | -------------------------- | -------------------------------------------------- |
| 실행 위치 | 브라우저(`localhost:6006`) | **Tauri 앱 안**(실제 WebView, 실제 폰트, 실제 창)  |
| 단위      | 컴포넌트 하나, 상태 하나씩 | 계층 전체를 한 페이지에 시트처럼                   |
| 강점      | 개별 props 조절, 문서      | 전체 일관성 비교, 테마 동시 비교, 실제 앱 스크린샷 |

**단일 소스:** 견본은 컴포넌트 옆의 `*.stories.tsx`(CSF3) 하나로 정의한다. Debug 화면은 `import.meta.glob('/src/components/**/*.stories.tsx')`로 스토리를 모두 불러와 `composeStories`(Storybook portable stories)로 렌더링한다. 따라서 **견본을 두 번 작성하지 않는다.**

## 3. 진입 · 빌드 제외

- **경로:** `#/debug`, 개발 빌드에서만 존재한다.
- **단축키:** `⌘⇧D`, 개발 빌드 전용.
- **번들 제외:** `if (import.meta.env.DEV) { const Debug = lazy(() => import('@/debug')) }` 형태로 동적 import한다. 릴리스 번들에 `src/debug/`가 없는지 빌드 결과물에서 확인한다.
- **저장 계층:** 실제 워크스페이스를 건드리지 않도록 `lib/storage`의 **메모리 구현**을 쓴다.

## 4. 화면 구성

```
┌──────────────┬──────────────────────────────────────────────────────┐
│ Debug        │ 툴바: [테마 L|D|L+D] [포인트 색 ▾] [글꼴 크기] [폭 1440|1024]  │
│ ─────────    │       [모션 줄이기] [상태 강제 ▾] [그리드 오버레이] [검색…]     │
│ ▸ Tokens     ├──────────────────────────────────────────────────────┤
│ ▸ L1 UI      │ UI-Button                    Ready · 감사 완료 · 시트 §2 │
│ ▸ L2 Overlay │ ┌─ Light ───────────────┐ ┌─ Dark ────────────────┐      │
│ ▸ L3 Shell   │ │ primary  D H A F X     │ │ primary  D H A F X     │      │
│ ▸ L4 Editor  │ │ secondary …            │ │ …                      │      │
│ ▸ L5 Page    │ └───────────────────────┘ └───────────────────────┘      │
│ ▸ Playground │ UI-IconButton …                                        │
│ ─────────    │                                                        │
│ 진행 요약     │                                                        │
│ Ready 12/58  │                                                        │
└──────────────┴──────────────────────────────────────────────────────┘
```

- **왼쪽 내비게이션:** `components.md`의 계층과 ID 순서 그대로 둔다. ID 옆에 진행 상태 배지(계획/구현/Ready/감사 완료)를 표시한다.
- **본문:** 컴포넌트마다 제목(ID · 이름 · 상태 · 시트 섹션)을 두고, 모든 스토리를 격자로 배치한다.
- **진행 요약:** 계층별 Ready 수 / 전체 수를 표시한다. 로드맵의 게이트 판단에 쓴다.

### 툴바 기능

| 기능            | 동작                                                                                                                                                                                                                                 |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 테마            | 라이트 / 다크 / **나란히(L+D)**. 나란히 보기는 각 열에 `data-theme`을 따로 적용한다                                                                                                                                                  |
| 포인트 색       | 8종 전환 (`tokens.md` §3)                                                                                                                                                                                                            |
| 글꼴 크기       | `--font-scale` 0.9 / 1 / 1.1                                                                                                                                                                                                         |
| 폭              | 1440 / 1024 프리셋. Tauri 창 크기를 바꾸거나 본문 폭을 제한한다                                                                                                                                                                      |
| 모션 줄이기     | `prefers-reduced-motion`을 흉내 내는 클래스를 켠다                                                                                                                                                                                   |
| 상태 강제       | hover / active를 모든 견본에 강제로 적용한다. 컴포넌트는 `:hover`와 함께 `[data-force=hover]`에도 같은 스타일을 주도록 Tailwind 커스텀 variant(`force-hover:`, `force-active:`)를 쓴다. 포커스는 강제하지 않고 Tab 이동으로 확인한다 |
| 그리드 오버레이 | 4px 격자와 요소 경계를 표시해 간격 리듬을 확인한다                                                                                                                                                                                   |
| 검색            | 컴포넌트 ID와 이름으로 필터링한다                                                                                                                                                                                                    |

툴바 설정은 URL 해시 쿼리(`#/debug?theme=both&accent=teal`)에 남겨, 같은 상태로 스크린샷을 다시 찍을 수 있게 한다.

## 5. 섹션 상세

| 섹션       | 내용                                                                                                                                                            |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tokens     | 실제 CSS 변수를 읽어 그리는 견본(값을 하드코딩하지 않는다): 색상, 소프트 컬러, 포인트 색, 타이포 스케일, 간격, 반경, 그림자, 모션 재생 버튼, lucide 아이콘 목록 |
| L1–L3, L5  | 해당 계층 컴포넌트의 모든 스토리                                                                                                                                |
| L4 Editor  | 블록별 스토리 + 슬래시 메뉴·플로팅 툴바를 열린 상태로 고정한 스토리                                                                                             |
| Playground | 실제 Tiptap 에디터 하나에 **모든 블록이 들어간 샘플 문서**(한국어 회의록)를 넣고 직접 편집해 본다. 슬래시 메뉴, 툴바, 드래그 핸들, 단축 입력을 실제로 확인한다  |

## 6. 레지스트리

`src/debug/registry.ts`에는 컴포넌트 ID별 **메타만** 둔다. 견본(스토리)은 §2의 `import.meta.glob`으로 찾고, 스토리 `title`의 ID(`"L1 UI/UI-Button"`)로 레지스트리와 연결한다. 스토리를 레지스트리에서 다시 import하지 않는다.

```ts
export const registry = {
  "UI-Button": { layer: "L1", status: "ready", sheet: "§2" },
  // …
} satisfies Record<ComponentId, DebugEntry>;
```

테스트로 세 가지를 검사한다.

1. `components.md`의 모든 ID가 레지스트리에 있다.
2. `status`가 `ready` 이상인 ID는 스토리가 하나 이상 있다.
3. 레지스트리에 없는 ID로 된 스토리가 없다.

## 7. 스크린샷 · 감사 흐름

1. `pnpm app` → `⌘⇧D`로 Debug 화면을 연다.
2. 섹션별 스크린샷을 찍는다(테마 L+D, 1440 기준).
3. OpenDesign `components.html`의 해당 섹션과 비교한다.
4. UI 감사를 하고, 결과를 `file:line` 목록으로 정리해 수정한다.
5. `registry.ts`의 상태를 갱신한다(`ready` → `audited`).

## 8. 구현 메모 (2026-11-19)

- **파일:** `src/debug/` — `debug-screen.tsx`(화면), `stories.ts`(스토리 로더), `registry.ts`(메타), `settings.ts`(툴바 설정 ↔ URL 해시), `tokens-section.tsx`, `sample-doc.ts`(Playground·ED-Editor 공용 문서), `debug.css`(그리드 오버레이).
- **진입:** `App.tsx`가 `import.meta.env.DEV`일 때만 `lazy(() => import("./debug/debug-screen"))`를 만든다. 릴리스 번들(`vite build`)에 Debug 문자열이 없는 것을 확인했다.
- **스토리 순서:** 모듈 네임스페이스는 export를 알파벳순으로 돌려주므로, 스토리 원문(`?raw`)에서 `export const` 순서를 읽어 파일에 적힌 순서대로 보여 준다.
- **모달 견본:** 화면 전체를 덮는 견본은 스토리 `parameters: { debug: { isolate: true } }`로 표시한다. Debug 화면은 이런 견본을 "열어 보기" 버튼으로 띄우고 Esc로 닫는다(현재 `OV-Dialog`).
- **포털 오버레이:** 팝오버·메뉴는 `body`로 포털되므로 테마 열이 아니라 문서 루트의 테마를 따른다. 나란히 보기에서는 라이트로 그려진다.
- **폭 프리셋:** Tauri에서는 창 크기를 바꾼다. 권한 `core:window:allow-set-size`는 `tauri.dev.conf.json`의 개발 전용 capability(`debug-screen`)에만 있다. "전체"로 돌아오면 프리셋을 고르기 전 창 크기로 되돌린다. 브라우저에서는 본문 최대 폭만 제한한다.
- **글꼴 크기:** `globals.css`의 `--text-body/code/h1–h3/title`이 `--font-scale`을 곱한다(본문 계열만).
- **남은 것:** `lib/storage` 메모리 구현은 저장 계층(Phase 5)과 함께 만든다.
