# MCP 서버 (AI 연결) — DATA-12

CetusNote 노트를 Claude Code나 Claude Desktop에서 읽고 쓸 수 있게 하는 MCP 서버예요.
별도 프로그램을 설치할 필요 없이 앱 실행 파일에 `--mcp` 옵션을 붙이면 됩니다. 창은 뜨지 않고,
표준 입출력(stdio)으로만 통신해요. 네트워크 포트는 열지 않아요.

결정 기록은 [architecture.md](../architecture.md)의 ADR-026에 있어요.

## 연결하기

설정 → 데이터 아래 「AI 연결(MCP)」에서 명령을 복사할 수 있어요. 아래는 직접 적는 방법이에요.

### Claude Code

```sh
claude mcp add cetusnote -- "/Applications/CetusNote.app/Contents/MacOS/cetusnote" --mcp
```

### Claude Desktop

`claude_desktop_config.json`(macOS: `~/Library/Application Support/Claude/`)의 `mcpServers`에 넣어요.

```json
{
  "mcpServers": {
    "cetusnote": {
      "command": "/Applications/CetusNote.app/Contents/MacOS/cetusnote",
      "args": ["--mcp"]
    }
  }
}
```

설정을 바꾼 뒤에는 클라이언트를 다시 시작해요.

## 연결 상태 (설정 › Agent / MCP)

- 설정의 「Agent / MCP」 탭에서 연결 뱃지를 본다: **연결됨**(이 워크스페이스에 붙은 `--mcp` 서버가 있다) · **설정됨**(Claude Code `~/.claude.json` 또는 Claude Desktop `claude_desktop_config.json`에 이 앱의 `--mcp` 항목이 있다) · **연결 안 됨**. 3초마다, 창으로 돌아올 때 다시 읽는다.
- 연결 표시: `--mcp` 서버가 연결(initialize)되면 `<워크스페이스>/.cache/mcp/<pid>.json`에 클라이언트 이름·시각·프로세스 시작 시각을 쓰고, 정상 종료하면 지운다(`mcp/presence.rs`). 강제 종료로 남은 파일은 읽을 때 pid 생존·시작 시각으로 걸러 지운다.
- 클라이언트 설정 파일은 읽기만 하고 있음/없음만 쓴다(수정 시각으로 결과를 기억). `CLAUDE_CONFIG_DIR`가 있으면 그 안의 `.claude.json`을 본다.
- 같은 탭의 「AI 에이전트」는 개인 AI 에이전트·API 키 연결(검색·내용 분석) 자리다. 아직 준비 중.

## 어느 워크스페이스를 쓰나

- 기본: 앱이 마지막으로 연 워크스페이스. 앱에서 워크스페이스를 한 번이라도 열어 둬야 해요.
- 다른 폴더를 쓰려면 `--workspace <폴더>`를 붙여요. 그 폴더에는 `pages/` 또는 `workspace.json`이 있어야 하고, 없으면 만들지 않고 실패해요.

```sh
/Applications/CetusNote.app/Contents/MacOS/cetusnote --mcp --workspace "$HOME/Documents/CetusNote"
```

## 도구

| 도구             | 하는 일                                                                                                                             | 읽기 전용 | 파괴적 | 같은 입력 반복 |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------- | --------- | ------ | -------------- |
| `list_pages`     | 페이지 목록. `format`: `flat`(기본) 또는 `tree`(들여쓴 개요). `parent_id` 아래만, `limit`(기본 50, 최대 200)과 `cursor`로 나눠 받기 | 예        | 아니요 | 예             |
| `search_pages`   | 제목과 본문에서 찾기. 낱말을 여러 개 주면 모두 들어 있는 페이지만 (대소문자 무시)                                                   | 예        | 아니요 | 예             |
| `read_page`      | 페이지 한 개. 본문은 Markdown(기본) 또는 `tiptap_json`                                                                              | 예        | 아니요 | 예             |
| `create_page`    | 제목·부모·Markdown 본문으로 새 페이지                                                                                               | 아니요    | 아니요 | 아니요         |
| `append_to_page` | 본문 끝에 덧붙이기. 기존 내용은 그대로                                                                                              | 아니요    | 아니요 | 아니요         |
| `update_page`    | 제목 바꾸기 또는 본문을 통째로 바꾸기 (바꾸기 전 버전을 남김)                                                                       | 아니요    | 예     | 예             |
| `move_page`      | 다른 페이지 아래로 옮기기. `parent_id`가 null이면 최상위                                                                            | 아니요    | 아니요 | 예             |
| `trash_page`     | 휴지통으로 옮기기. 영구 삭제는 하지 않아요                                                                                          | 아니요    | 예     | 예             |

오류는 도구 결과의 `isError`로 돌아와요. 모델이 메시지를 보고 다시 시도할 수 있게 한국어 문장으로 적어요.
잘못된 페이지 id(`../` 같은 경로 조각 포함), 없는 페이지, 휴지통이나 템플릿 페이지에 쓰기 같은 경우예요.

## 리소스

| 주소                    | 내용                                                      |
| ----------------------- | --------------------------------------------------------- |
| `cetusnote://page/{id}` | 페이지 한 개를 Markdown으로 (제목, id·부모·태그 줄, 본문) |
| `cetusnote://tree`      | 보이는 페이지 전체의 들여쓴 개요                          |

목록에는 `cetusnote://tree`와 페이지 200개까지가 올라와요.

## 앱과 같이 쓸 때

- 쓰기는 앱이 쓰는 것과 같은 파일에 원자적으로 저장돼요(임시 파일 후 이름 바꾸기).
- 바꾸기·덧붙이기·옮기기·휴지통으로 옮기기 전에 그 페이지의 바꾸기 전 내용을 버전 기록에 남겨요(DATA-09). 앱의 「버전 기록」에서 되돌릴 수 있어요.
- 앱이 열려 있을 때 바깥에서 파일이 바뀌면 앱이 「외부에서 바뀌었어요」를 띄우고 다시 불러와요(DATA-07).
- **앱에 저장되지 않은 편집이 있는 페이지에 MCP가 쓰면 앱 쪽이 이겨요.** 앱의 편집 내용이 우선이고, MCP가 쓴 내용은 앱이 다시 불러올 때 사라질 수 있어요. 앱에서 그 페이지를 닫은 뒤 다시 쓰는 것을 권해요.
- 같은 내용으로 다시 쓰면 파일을 건드리지 않아요(`changed: false`).

## Markdown 변환

Markdown은 앱의 Tiptap 문서로 바뀌어 저장돼요. 쓰는 형식은 앱의 Markdown 내보내기(DATA-04)와 같아요. 읽을 때(문서 → Markdown)와 쓸 때(Markdown → 문서)를 모두 맞춰요.

- 다룸: 제목 1–6, 문단, 글머리·번호·할 일 목록(중첩), 인용, 코드 블록(언어 포함, `ts` 같은 줄임말은 `typescript`처럼 목록 이름으로 저장해요), 구분선, **굵게**, _기울임_, ~~취소선~~, `코드`, 링크, 표(첫 줄이 머리, `|`는 `\|`), 수식(`$…$`, `$$…$$`), 날짜 칩(`@2026-11-30`, 날짜가 맞을 때만), 콜아웃(`> [!NOTE] 💡 …`, 표준 없는 색은 `[!CETUS-<색>]`), 토글(`<details>`), 제목 토글(`<details><summary><h2>…</h2></summary>`), 열(`<!-- cetusnote:columns -->` 표지와 너비), 페이지 멘션·하위 페이지·첨부(`cetusnote://page/<id>` 링크, 첨부는 경로 링크).
- 글로 남음: 그림은 `![설명](주소)`로 내보내지만 가져올 때는 설명 글자가 돼요(그림 블록을 만들지 않아요). 표 안의 여러 문단은 `<br>`로 이어져요.
- 가져올 때 페이지 존재를 확인하지 않아요. `cetusnote://page/<id>` 링크는 멘션이 아니라 링크로 남아요. 하위 페이지는 제목을 모르므로 `하위 페이지`로 내보내고, 경로 표시 블록은 빈 블록이 돼요(앱의 복사와 같아요).
- 아직 다르게 동작하는 것: 목차 블록(내보내지 않음), 이모지 노드(글자로 나오지 않음), 언어를 정하지 않은 코드 블록(앱은 추측한 언어를 쓰고 MCP는 빈 언어로 둬요), 글자색(버림).
- 할 일과 보통 항목이 섞인 목록은 연속된 덩어리마다 목록을 나눠요.

## 한계

- 검색은 호출할 때마다 페이지 파일을 다시 읽어요. 페이지가 수천 개면 느릴 수 있어요.
- 템플릿은 목록과 검색에서 빠져요. 휴지통은 `include_trashed`를 켜야 보여요. 휴지통 페이지의 자식도 함께 숨어요(앱의 트리와 같아요).
- 서버는 요청을 한 번에 하나씩 처리해요.
- Windows 빌드는 GUI 전용 실행 파일이라 `--mcp`의 표준 입출력이 콘솔에 붙지 않을 수 있어요(미확인).
- 앱이 페이지 파일 형식(`schemaVersion`)을 올리면 서버의 `PAGE_SCHEMA_VERSION`도 함께 맞춰야 해요.

## 확인하기 (개발자)

```sh
cd src-tauri && cargo build
target/debug/cetusnote --mcp --workspace <폴더>
```

표준 입력에 JSON-RPC 줄을 보내면 응답이 표준 출력에 나와요. 로그는 모두 표준 오류로 나와요.
자동화된 스모크 테스트는 `initialize` → `notifications/initialized` → `tools/list` → `tools/call` 순서로 보내는 방식이에요.
