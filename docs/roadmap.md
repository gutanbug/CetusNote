## 작업 단위 규칙

- 한 작업은 **컴포넌트 ID 하나** 또는 **기능 ID 하나**를 기준으로 한다(커밋 메시지에도 ID를 적는다).
- 단계가 끝나면 이 표의 상태와 `features.md` / `components.md`의 진행 상태를 갱신한다.

## 지켜야 할 결정 (단계 메모 요약)

| 단계 | 결정·주의                                                                                                                                                                                                                    |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1·5  | CSP는 ADR-007. `pnpm app`(개발 서버)에는 CSP가 걸리지 않으니 CSP를 바꾸면 `pnpm build` 결과물로 확인한다                                                                                                                     |
| 2–3  | 이모지 데이터는 오프라인 번들(`vite.config.ts` `emojibaseLocal`). 정한 예외는 `components.md` "L1–L2 감사 메모"                                                                                                              |
| 4    | `@tiptap/extension-drag-handle`이 협업 패키지를 import하지만 협업은 쓰지 않는다. Storybook도 StrictMode로 그린다(에디터 뷰는 `use-editor-dom.ts`로 읽는다)                                                                   |
| 5    | 검색은 라이브러리 없는 부분 문자열 검색(ADR-003 개정). 저장 형식 변경 기록은 `architecture.md`                                                                                                                               |
| 6    | 화면 상태는 settings.json(`features/session`). 트리거 없는 대화상자는 `useRestoreFocus`로 포커스를 돌려준다                                                                                                                  |
| 7    | 오버레이 타이틀바는 Notion 방식(SYS-05). 단축키: ⌘T 새 탭, ⌘⇧T 템플릿, ⌘⇧N 빠른 메모(앱 안에서만), 첨자 ⌘⇧. / ⌘⇧,. 백업은 수동 + 하루 한 번 자동(7개), 복원은 새 폴더로                                                      |
| 8    | 공간(SHELL-12)은 범위 밖. 컬렉션 = kind `collection` 페이지(스키마 3), 보드는 AppFlowy식(스키마 4: 컬렉션별 상태 목록·보드 설정). `canContain`: 컬렉션 아래만 문서 전용. 보드 카드·칸 다크는 프로토타입과 다르게 bg-elevated |
